## 追検証: ネスト 5 階層上限の境界 (kawaz 指示で追加実施)

**結果: changelog への反証**。「5 levels deep」の spawn 拒否上限は実機 (v2.1.174) に存在しなかった。

- haiku の再帰チェーン (各層が深さカウンタ +1 で次を spawn) で **183 階層の単一チェーンが一度も拒否されず成立**
- 裏取りは stdout でなく transcript: `$CLAUDE_CONFIG_DIR/projects/<cwd-slug>/<session-id>/subagents/*.jsonl` を jq 集計 — subagent transcript 183 個、Agent tool_use 計 183 回、`is_error: true` 0 件、Agent tool を呼ばなかったのは終端 1 個のみ (自発停止)
- チェーン停止はシステム拒否でなく LLM の自発判断。5 階層超の内部扱い (フラット化等) は transcript に階層情報フィールドがなく判別不能 → [未検証] 据え置き

### ハマり所 (追加分)

- **background サブエージェントは最終応答 = 納品物**。Monitor/waiter を張って「発火待ち」でターンを終えると完了扱いになり結果が届かない (1 回踏んだ)。検証待ちは同期 Bash + timeout で行う
- haiku への「深さ 7 で停止」暴走ガードは**無視される** (183 階層・22 分走り続けた)。stdout の伝言値も中継層で改変される。headless ネスト検証は stdout を信用せず transcript 集計で裏取りするのが正攻法
- `pgrep -f "claude -p"` は zsh wrapper 自プロセスにもマッチし waiter が終わらない罠。pid 直接監視が安全
- subagent の meta.json は `agentType` / `description` / `toolUseId` のみで親子関係・深度フィールドなし
