## 新発見

- **Edit は実行前に Read を伴う**: `Edit src/app.ts` 時、`Edit(src/**)` だけでなく `Read(src/**)` の
  `if` も評価・発火する。Edit 専用 hook を書いても同 path の Read 系 `if` が先に走る。doc に注記追加。
- 相対 glob (`src/**` / `out/**`) は **project dir 基準**で解決される (絶対 path ではない)。

## 適用余地レビュー (runbook §6 を新設してこのパスで初運用)

新 capability を理解したタイミングで「既存自作資産を簡単化/堅牢化/陳腐化させないか」を逆引きする
ステップを runbook に追加 (§6、旧仕上げは §7)。今回の候補:

- **Bash `if` のサブコマンド単位パース** → 既存 guard 系 plugin (`claude-push-guard` /
  `claude-bash-safety` / draft `gh-issue-guard`) の自前 regex パースを補助できる可能性。
  `if: "Bash(git *)"` は `FOO=bar jj git push` の leading assignment 除去・`$()` 内判定を
  ランタイム側でやってくれるので、手製 regex の取りこぼし (= `$()`/leading var) を減らせる。
  - 限界: guard は「マッチ後に repo owner 抽出/文面生成」もするので `if` は第1段フィルタ止まり
    (script 側パースは残る)。深いパターン `Bash(git push *)` は fail-open (guard では安全側)。
  - routing: 対象は別リポ → `dogfooding-feedback-upstream` に従い各リポ `docs/issue/` 起票 or
    担当セッション共有。**本リポでは実装しない** (kawaz の判断待ち)。

- CHANGELOG が例示した `Read(~/.ssh/**)` の **`~` ホーム展開 glob** は、検証サブエージェントが安全のため

## 次回担当 agent への申し送り (検証ハーネス)

- file 系 tool の `if` 検証は、hook command を「marker を log に追記して exit 0」にして発火痕を残す方式が楽。
  claude -p に「use the Read/Edit/Write tool, not Bash」と明示し、`--verbose --output-format stream-json` の
  tool 呼び出しを grep して実使用 tool を切り分ける。
- Edit ケースは Read 系 `if` も巻き込むので、Edit 専用 marker の有無で主眼挙動を切り分ける。
