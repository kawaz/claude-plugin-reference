CHANGELOG は generic に「`Tool(param:value)` を追加」と書いているが、実機では native matcher を持つ tool で次の warning を出して **rule loader が当該 rule を無視** する:

```
Permission deny rule "Bash(command:...)" targets command as a raw string and will not match — use Bash(…) for Bash's own matcher.
Permission deny rule "Read(file_path:...)" targets file_path as a raw string and will not match — use Read(…) for Read's own matcher.
```

→ `Bash(command:*git*)` のような書き方は黙って allow 化する罠。reference には注意書きを 1 段落確保 (hooks.md §3 末尾)。`Task(subagent_type:codex*)` は loader 受理 OK、deny 動作は subagent spawn を伴うため未検証 (hooks.md §10.5 TODO 行き)。

## 新発見 / 検証ハーネスの注意点

### `--permission-mode bypassPermissions` は workspace trust dialog を解除しない

claude を temp dir で起動すると `Ignoring N permissions.allow entries from .claude/settings.json: this workspace has not been trusted.` の警告が出て `permissions.allow` が破棄される。さらに auto-mode classifier が `.claude.json` への trust 書き込みを self-modification として deny する。

**回避**: `--settings ./<file>.json` 経路で settings を引数渡しすると、`permissions.allow` は依然適用されないものの、**`permissions.deny` と `hooks` は適用される** (= permission gating / hook 発火検証はこれで十分)。今回の検証はすべてこの経路で実施。

### 個人 hook plugin の干渉回避

`CLAUDE_PROJECT_DIR` / `CLAUDE_CONFIG_DIR` は触らず、**temp dir を cwd にする** だけで:
- project scope hook は新 temp project = 無し
- user scope hook (`~/.claude-personal/`) はそのまま読まれる
- push-guard / bash-safety 等の発火は cwd 起点判定なので最小化される

`Bash(... && ...)` の bash-safety 分割警告は出るが、検証対象 hook の発火可否には影響しない。

### Workflow tool 経由の triage + 7 並列 apply パターン

今回の workflow script (`workflows/scripts/cc-version-maintenance-wf_48e9ac1a-c2f.js`) は雛形として再利用可能。

- triage agent は CHANGELOG + npm publish 日付を取り、7 file 別の TODO リストを structured output で返す
- apply agent は対応 TODO の有無で起動/不要を分岐 (今回は 7/7 起動、commands.md だけ既出で no-op)
- script 編集 → `Workflow({scriptPath, resumeFromRunId})` で triage cache 効く

途中で kawaz feedback (`reference-lean-details-to-journal`) を apply prompt に入れ忘れたが、TaskStop → script edit → resume で triage cache が活きて損失ゼロ。次回は triage 起動前に **kawaz feedback memory を先に load する** こと。
